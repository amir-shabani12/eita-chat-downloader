# دانلودگر فایل گفتگوی ایتا

**Eitaa Chat File Downloader** — افزونه گوگل کروم برای بررسی تمام تاریخچه یک گفتگوی شخصی در [ایتا وب](https://web.eitaa.com/)، شناسایی پیوست‌ها و دانلود گروهی بر اساس پسوند.

ابتدا فایل‌های گفتگو فهرست می‌شوند؛ سپس می‌توانید پسوندهایی مثل `pdf`، `zip` یا `mp4` را انتخاب کنید و همه فایل‌های مربوط به آن‌ها را دانلود کنید.

> وضعیت پروژه: نسخه اولیه. آزمون‌های خودکار با داده شبیه‌سازی‌شده انجام شده‌اند؛ سازگاری با حساب واردشده و دانلود واقعی هنوز به‌صورت سرتاسری تأیید نشده است.

## امکانات

- بررسی تاریخچه از جدیدترین تا قدیمی‌ترین پیام، بدون سقف قراردادی تعداد پیام.
- فعال‌شدن دانلود تنها پس از دریافت نشانه پایان تاریخچه از ایتا.
- نمایش نام، پسوند، تعداد، حجم و وضعیت فایل‌ها.
- انتخاب چند پسوند یا همه پسوندها، همراه با دسته «بدون پسوند».
- دانلود ترتیبی، توقف عملیات و ادامه بررسی از نقطه ذخیره‌شده.
- تلاش دوباره برای فایل‌های ناموفق و ردکردن فایل‌های قبلاً ذخیره‌شده.
- حفظ فایل‌های همنام با افزودن شناسه پیام به نام فایل.
- جستجو در فهرست فایل‌ها و خروجی محلی JSON.
- رابط فارسی و راست‌به‌چپ، بدون نیاز به سرور یا نصب وابستگی برای استفاده.

## پیش‌نیازها

- گوگل کروم نسخه **۱۲۰ یا بالاتر**.
- ورود به `https://web.eitaa.com/` در همان مرورگری که افزونه نصب شده است.
- بازبودن گفتگوی عادی با شخص موردنظر.

Node.js فقط برای اجرای تست‌های توسعه لازم است.

## نصب دستی در کروم

1. کد پروژه را با **Code → Download ZIP** از گیت‌هاب دانلود و استخراج کنید، یا مخزن را clone کنید.
2. در کروم، آدرس `chrome://extensions` را باز کنید.
3. گزینه **Developer mode** را روشن کنید.
4. روی **Load unpacked** بزنید و پوشه [`extension`](./extension/) را انتخاب کنید؛ فایل `manifest.json` باید مستقیماً داخل پوشه انتخابی باشد.
5. افزونه را از منوی Extensions کروم سنجاق کنید تا آیکون آن در دسترس باشد.

اگر از بسته مستقل `eitaa-file-downloader.zip` استفاده می‌کنید، پس از استخراج، پوشه‌ای را انتخاب کنید که `manifest.json` مستقیماً داخل آن قرار دارد.

## روش استفاده

1. وارد ایتا وب شوید و گفتگوی شخص موردنظر را باز کنید.
2. روی آیکون افزونه بزنید؛ صفحه مدیریت در یک زبانه مستقل باز می‌شود.
3. زبانه ایتا را انتخاب و **اتصال به گفتگوی باز** را بزنید. نام و شناسه گفتگو را بررسی کنید.
4. **بررسی تمام تاریخچه** را بزنید و منتظر پیام **بررسی کامل شد** بمانید.
5. پسوندهای موردنظر را انتخاب کنید.
6. روی **دانلود پسوندهای انتخابی** بزنید.

در طول عملیات، صفحه مدیریت و زبانه ایتا را باز نگه دارید و حساب یا گفتگوی فعال را تغییر ندهید. خواب سیستم یا تعلیق زبانه ممکن است عملیات را متوقف کند.

برای ادامه پس از بستن صفحه مدیریت، دوباره به همان گفتگو متصل شوید. نقطه ادامه بررسی و وضعیت فایل‌ها از حافظه محلی بازیابی می‌شود. برای پوشش پیام‌های جدید، **بررسی دوباره از ابتدا** و سپس **بررسی تمام تاریخچه** را بزنید؛ وضعیت دانلودهای موفق حفظ می‌شود.

### محل ذخیره فایل‌ها

فایل‌ها در پوشه دانلود پیش‌فرض کروم، با این ساختار ذخیره می‌شوند:

```text
Downloads/
└── Eitaa/
    └── شناسه حساب و گفتگو/
        └── پسوند/
            └── شناسه‌پیام_نام‌فایل.pdf
```

اگر گزینه **Ask where to save each file before downloading** در تنظیمات کروم روشن باشد، کروم برای هر فایل مقصد می‌پرسد. برای ذخیره بدون پرسش می‌توانید این گزینه را خاموش کنید.

## بررسی تمام تاریخچه چگونه انجام می‌شود؟

افزونه از رابط داخلی مدیر تاریخچه ایتا استفاده می‌کند و به پیام‌های قابل مشاهده یا اسکرول صفحه محدود نیست:

1. تاریخچه از جدیدترین پیام، در صفحه‌های حداکثر ۱۰۰تایی خوانده می‌شود.
2. شناسه قدیمی‌ترین پیام هر صفحه، نشانگر دریافت صفحه بعد است.
3. فایل‌های صفحه و نشانگر ادامه، در یک تراکنش IndexedDB ذخیره می‌شوند.
4. فقط نشانه صریح `isEnd.top` در پاسخ ایتا، بررسی را کامل می‌کند. صفحه کوتاه، خطا یا تکرار نشانگر به‌تنهایی نشانه تکمیل نیست.
5. پس از تکمیل، انتخاب پسوندها برای دانلود قابل استفاده است.

منظور از «تمام تاریخچه»، تاریخچه‌ای است که حساب شما از سرور ایتا دریافت می‌کند. پیام حذف‌شده، فایل منقضی‌شده، محتوای یک‌بارمصرف یا تاریخچه‌ای که سرور ارائه نمی‌دهد قابل بازیابی نیست. پیام‌های رسیده پس از شروع بررسی، به بررسی مجدد نیاز دارند.

## فایل‌های پشتیبانی‌شده و محدودیت‌ها

| مورد | پوشش |
| --- | --- |
| سند و فایل پیوست | هر پسوند؛ تشخیص از نام اصلی یا MIME شناخته‌شده |
| عکس | بزرگ‌ترین اندازه موجود در ایتا |
| ویدیو، فایل صوتی، ویس و استیکر | در صورت وجود به‌عنوان پیوست پیام |
| فایل با نوع ناشناخته | قابل انتخاب در دسته «بدون پسوند» |
| لینک داخل متن یا پیش‌نمایش وب‌سایت | دانلود نمی‌شود |
| عکس پروفایل | در فهرست پیوست‌های گفتگو نیست |
| گروه، کانال و موضوع | در این نسخه پشتیبانی نمی‌شود |

- ایتا فایل را ابتدا به Blob می‌دهد و سپس کروم آن را ذخیره می‌کند؛ دریافت فایل‌های بسیار بزرگ به حافظه کافی نیاز دارد.
- وضعیت **ذخیره شد** تنها پس از تأیید اتمام دانلود توسط کروم ثبت می‌شود.
- حذف دستی یک فایل از دیسک، وضعیت ذخیره‌شده آن را در فهرست افزونه تغییر نمی‌دهد.
- رابط‌های داخلی ایتا API عمومی و پایدار نیستند؛ تغییر آن‌ها می‌تواند به به‌روزرسانی افزونه نیاز داشته باشد.
- مبنای بررسی سازگاری، فایل‌های عمومی ایتا وب در تاریخ **۱۸ نوامبر ۲۰۲۶** بوده است.

## حریم خصوصی و مجوزها

افزونه از نشست واردشده خود ایتا استفاده می‌کند و رمز، کد ورود یا کلید نشست را استخراج نمی‌کند. متن پیام‌ها ذخیره نمی‌شود. فراداده فایل‌ها، شناسه حساب و گفتگو، نشانگر ادامه و وضعیت دانلودها فقط در IndexedDB افزونه روی همان مرورگر نگهداری می‌شوند.

| مجوز | کاربرد |
| --- | --- |
| `https://web.eitaa.com/*` | دسترسی به زبانه ایتا وب |
| `scripting` | اجرای آداپتر تاریخچه و فایل در صفحه ایتا |
| `downloads` | آغاز دانلود و بررسی وضعیت ذخیره در کروم |

افزونه سرور واسط، آنالیتیکس یا کتابخانه خارجی ندارد. خروجی JSON یک فایل محلی است. **پاک‌کردن فهرست محلی این گفتگو** فقط اطلاعات افزونه را پاک می‌کند و پیام‌های ایتا یا فایل‌های دانلودشده را حذف نمی‌کند.

## رفع اشکال

| مشکل | اقدام پیشنهادی |
| --- | --- |
| زبانه ایتا پیدا نمی‌شود | ایتا وب را در همان کروم باز کنید و «تازه‌سازی زبانه‌ها» را بزنید. |
| اتصال به گفتگو انجام نمی‌شود | ورود به حساب را کامل کنید و یک گفتگوی شخصی عادی باز کنید. |
| حساب یا گفتگو تغییر کرده است | به همان حساب و گفتگوی انتخاب‌شده برگردید و ادامه دهید. |
| بررسی متوقف شده یا کامل نشده است | پس از برقراری اتصال، «ادامه بررسی تاریخچه» را بزنید. |
| خطای `FLOOD_WAIT` | به‌اندازه زمان نمایش‌داده‌شده صبر کنید و دوباره ادامه دهید. |
| فایل ناموفق است | «تلاش دوباره برای ناموفق‌ها» را بزنید؛ فایل حذف‌شده یا منقضی‌شده قابل بازیابی نیست. |
| دانلود در کروم متوقف شده است | وضعیت آن را در `chrome://downloads` بررسی کنید. |
| بعد از تغییر کد رفتار قبلی دیده می‌شود | در `chrome://extensions` افزونه را Reload کنید و صفحه مدیریت را دوباره باز کنید. |

هشدارها و محدودیت‌های امنیتی کروم همچنان اعمال می‌شوند؛ افزونه آن‌ها را دور نمی‌زند.

## ساختار پروژه

```text
extension/
├── manifest.json       # تنظیمات و مجوزهای افزونه
├── background.js       # ارتباط با زبانه‌ها و API دانلود کروم
├── page-adapter.js     # اتصال به مدیر تاریخچه و فایل ایتا
├── core.js             # تشخیص پیوست، پسوند و نام امن فایل
├── store.js            # ذخیره فهرست و نشانگر ادامه در IndexedDB
├── dashboard.html      # صفحه مدیریت فارسی
├── dashboard.css       # ظاهر صفحه مدیریت
└── dashboard.js        # روند بررسی، انتخاب و دانلود

tests/
├── extension.test.cjs  # آزمون‌های خودکار
├── preview-server.cjs  # سرور محلی پیش‌نمایش با داده آزمایشی
└── preview.js          # شبیه‌ساز ارتباط برای پیش‌نمایش
```

پوشه `research` شامل فایل‌های عمومی بررسی‌شده برای سازگاری است و برای نصب افزونه لازم نیست. این پوشه در بسته نصب مستقل قرار ندارد.

## توسعه و تست

تست‌ها به Node.js نسخه **۲۰ یا بالاتر** نیاز دارند و با ابزارهای داخلی Node اجرا می‌شوند؛ نصب پکیج لازم نیست:

```sh
node --test tests/extension.test.cjs
```

پوشش تست‌ها شامل پیمایش ۲۳۵۷ پیام، ادامه از نشانگر، صفحه تکراری یا ناقص، تغییر حساب و گفتگو، پیوست حذف‌شده، تشخیص پسوند، نام امن فایل، آماده‌سازی Blob و توقف دریافت بزرگ است. این آزمون‌ها جایگزین تست سرتاسری در کروم و حساب واقعی نیستند.

برای پیش‌نمایش رابط با داده آزمایشی:

```sh
node tests/preview-server.cjs
```

سپس [پیش‌نمایش محلی](http://127.0.0.1:18769/) را باز کنید. این حالت به حساب ایتا وصل نمی‌شود و دانلود واقعی انجام نمی‌دهد.

## گزارش مشکل و مشارکت

برای گزارش خطا در Issues، نسخه کروم، نسخه افزونه، مرحله وقوع خطا و متن خطا را بنویسید. پیش از ارسال تصویر یا خروجی JSON، اطلاعات خصوصی گفتگو و فایل‌ها را حذف کنید.

برای مشارکت، تغییرات را در یک شاخه جدا انجام دهید، تست‌ها را اجرا کنید و Pull Request را با توضیح تغییر و روش بررسی آن بفرستید.
